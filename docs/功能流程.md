## 1. 启动层流程

### 1.1 入口分发流程

```
用户双击 exe 或输入命令
        │
        ▼
   src/__main__.py
   └── main()
         │
         ├── 无参数（双击 exe）
         │   └── 追加 "gui" → 调用 cli.app()
         │
         ├── novel2script gui
         │   └── start_gui() → PyWebView 窗口
         │
         ├── novel2script serve
         │   └── start_serve() → 浏览器模式
         │
         ├── novel2script convert <file>
         │   └── run_convert() → CLI 转换模式
         │
         └── novel2script config
             └── show_config() → 配置管理
```

### 1.2 回退机制流程

```
start_gui() 启动桌面模式
        │
        ▼
  尝试 import webview（PyWebView）
        │
        ├── 成功（已安装 pywebview）
        │   └── DesktopApp().start() → PyWebView 窗口
        │
        └── 失败（ImportError）
            ├── 打印提示："⚠️ pywebview 未安装，使用浏览器模式"
            ├── webbrowser.open(f"http://{host}:{port}")
            └── uvicorn.run(fastapi_app, ...)
```

### 1.3 各方法作用

| 文件 | 方法 | 作用 |
|------|------|------|
| `src/__main__.py` | `main()` | 入口分发：无参数时默认 gui，调用 `cli.app()` |
| `src/cli.py` | `gui()` | 启动桌面窗口模式（默认命令） |
| `src/cli.py` | `serve()` | 启动 Web UI 模式（浏览器访问） |
| `src/cli.py` | `convert()` | CLI 转换模式：输入文件 → 输出 YAML |
| `src/cli.py` | `config()` | 查看/修改配置 |
| `src/cli.py` | `skill_run()` | CLI 运行指定 Skill |
| `src/cli.py` | `skill_list()` | CLI 列出所有 Skill |
| `src/desktop/window.py` | `DesktopApp.start()` | 后台线程运行 FastAPI，前台创建 PyWebView 窗口 |
| `src/desktop/window.py` | `_run_server()` | 在新线程中运行 uvicorn |
| `src/desktop/window.py` | `_wait_for_server()` | 等待 FastAPI 服务就绪（超时 10 秒） |

## 2. API 层流程

### 2.1 请求生命周期

```
前端请求（PyWebView 或浏览器）
        │
        ▼
   FastAPI 中间件链
   ├── CORS 中间件
   ├── 日志中间件
   └── 错误处理中间件
        │
        ▼
   api/main.py → FastAPI app
   ├── lifespan() 事件
   │   ├── 启动：加载配置 → 初始化 LLMClient → 初始化 SkillManager → 发现 Skill
   │   └── 关闭：清理临时文件
   │
   └── 路由分发
        │
        ├── /api/v1/convert/*  → convert_router
        ├── /api/v1/config/*    → config_router
        ├── /api/v1/files/*    → files_router
        ├── /api/v1/projects/* → projects_router
        ├── /api/v1/editor/*  → editor_router
        ├── /api/v1/skills/*  → skills_router
        └── /*（兜底）          → StaticFiles（前端页面）
```

### 2.2 项目管理 API 流程

```
GET /api/v1/projects
        │
        ▼
   projects.py → list_projects()
        │
        ▼
   app.state.project_store.list_projects()
        │ 参数：search / sort_by / order
        │
        ▼
   返回 ProjectListItem[]（JSON）
```

```
POST /api/v1/projects
        │
        ▼
   projects.py → create_project()
        │ 参数：title / novel_text
        │
        ▼
   app.state.project_store.create_project()
        │ 1. 生成 project_id（uuid4().hex）
        │ 2. 创建目录 ~/.novel2script/projects/<id>/
        │ 3. 写入 novel.txt / script.yaml / meta.json / config_snapshot.json
        │
        ▼
   返回 ProjectDetail（JSON）
```

```
PUT /api/v1/projects/{id}/novel
        │
        ▼
   projects.py → save_novel()
        │ 参数：content（小说原文）
        │
        ▼
   app.state.project_store.save_novel()
        │ 1. 写入 novel.txt
        │ 2. 更新 meta.json（updated_at / novel_word_count）
        │
        ▼
   返回成功消息 → 触发 SSE 事件 `project_saved`
```

### 2.3 转换 API 流程

```
POST /api/v1/convert/start
        │
        ▼
   convert.py → start_convert()
        │ 参数：project_id / options
        │
        ▼
   创建后台任务（asyncio.Task）
        │ 1. 读取 novel.txt
        │ 2. 构建 PipelineContext
        │ 3. 调用 pipeline.run(context, callback)
        │ 4. 保存 script.yaml
        │
        ▼
   返回 { task_id, status: "running" }
```

## 3. 核心 Pipeline 流程

### 3.1 完整转换流程

```
pipeline.run(context, callback)
        │
        ▼
   【Hook: before_convert】
   └── 执行所有注册的 before_convert Hook
        │ （如：pre_processor Skill 执行）
        │
        ▼
   text_segmenter.segment(novel_text)
        │ 判断：文本长度 > segment_threshold（6000）？
        │   └── 是：按段落边界分段，每段保留前段末 200 字上下文
        │
        ▼
   ┌──────────────────────────────────────────────┐
   │ 步骤 1：character_extractor.run()          │
   │ 输入：全量 novel_text                     │
   │ 输出：context.characters（CharacterRegistry） │
   └──────────────────────────────────────────────┘
        │
        ├── Hook: after_step("character_extractor")
        │
        ▼
   ┌──────────────────────────────────────────────┐
   │ 步骤 2：scene_splitter.run()（按章并行）│
   │ 输入：chapters[] + characters         │
   │ 输出：context.scenes[]                  │
   └──────────────────────────────────────────────┘
        │
        ├── Hook: after_step("scene_splitter")
        │
        ▼
   ┌──────────────────────────────────────────────┐
   │ 步骤 3：dialogue_parser.run()（场景级并行）│
   │ 输入：scenes[] + characters         │
   │ 输出：context.beats[]（初步）        │
   └──────────────────────────────────────────────┘
        │
        ├── Hook: after_step("dialogue_parser")
        │
        ▼
   ┌──────────────────────────────────────────────┐
   │ 步骤 4：emotion_tagger.run()（场景级并行）│
   │ 输入：beats[] + scenes[]           │
   │ 输出：beats[]（含 emotion 字段） │
   └──────────────────────────────────────────────┘
        │
        ├── Hook: after_step("emotion_tagger")
        │
        ▼
   merger.merge(segments)
        │ 合并分段结果（如分段过）
        │ 保证角色 ID 全局唯一
        │
        ▼
   ┌──────────────────────────────────────────────┐
   │ 步骤 5：yaml_generator.run()                │
   │ 输入：beats[] + characters + scenes       │
   │ 输出：script（YAML 字符串）         │
   │ 校验：Pydantic model_validate()           │
   └──────────────────────────────────────────────┘
        │
        ├── Hook: after_step("yaml_generator")
        │
        ▼
   ┌──────────────────────────────────────────────┐
   │ 步骤 6：quality_checker.run()               │
   │ 输入：script（YAML）                   │
   │ 输出：conversion_notes[]             │
   └──────────────────────────────────────────────┘
        │
        ├── Hook: after_step("quality_checker")
        │
        ▼
   【Hook: after_convert】
   └── 执行所有注册的 after_convert Hook
        │ （如：post_processor Skill 执行）
        │
        ▼
   【Skill: exporter】（用户主动触发）
   └── 执行所有启用的 exporter Skill
        │ （如：fountain_export）
        │
        ▼
   返回最终 PipelineContext
```

### 3.2 进度回调流程

```
Pipeline.run()
        │
        ▼
   for each step_name in step_order:
        │
        │   callback.on_step_start(step_name, total, current)
        │   │
        │   ▼
        │   step.run(context)
        │   │ 过程中：
        │   │   callback.on_step_progress(step_name, detail, percent)
        │   │
        │   ▼
        │   返回更新后的 context
        │
        │   callback.on_step_complete(step_name, result_summary)
        │
        ▼
   【Hook: after_step】
        │
        ▼
   返回最终 context
```

### 3.3 Step 插件注册流程

```
用户代码或 Skill
        │
        ▼
   pipeline.register_step(name, step, after="emotion_tagger")
        │
        ▼
   Pipeline._steps[name] = step
        │
        ├── after = None：
        │   └── step_order.append(name)
        │
        └── after = "emotion_tagger"：
            └── idx = step_order.index("emotion_tagger")
                step_order.insert(idx + 1, name)
```

### 3.4 各方法作用

| 文件 | 方法 | 作用 |
|------|------|------|
| `core/pipeline.py` | `register_step()` | 注册步骤（可指定插入位置） |
| `core/pipeline.py` | `reorder_steps()` | 重排步骤执行顺序 |
| `core/pipeline.py` | `skip_steps()` | 设置跳过的步骤 |
| `core/pipeline.py` | `hook()` | 注册 Hook 回调 |
| `core/pipeline.py` | `run()` | 执行完整 Pipeline |
| `core/pipeline.py` | `run_chapters()` | 增量转换：只处理指定章节 |
| `core/pipeline.py` | `_fire_hook()` | 触发指定事件的所有 Hook |
| `core/pipeline.py` | `_validate_dependencies()` | 校验步骤依赖是否满足 |
| `core/steps/base.py` | `StepProtocol.name` | 步骤名称（唯一标识） |
| `core/steps/base.py` | `StepProtocol.run()` | 执行步骤 |
| `core/steps/base.py` | `StepProtocol.validate()` | 验证步骤输入是否合法 |
| `core/steps/character_extractor.py` | `run()` | 角色识别：LLM 提取 + 别名合并 |
| `core/steps/scene_splitter.py` | `run()` | 场景分割：按时空变化 |
| `core/steps/dialogue_parser.py` | `run()` | 对白解析：对白/动作/旁白分类 |
| `core/steps/emotion_tagger.py` | `run()` | 情绪标注：为 Beat 添加 emotion 字段 |
| `core/steps/yaml_generator.py` | `run()` | YAML 生成 + Pydantic 校验 |
| `core/text_segmenter.py` | `segment()` | 长文本智能分段（>6000 字） |
| `core/merger.py` | `merge()` | 分段结果合并（角色 ID 统一） |
| `core/project_store.py` | `ProjectStore.create_project()` | 创建新项目 |
| `core/project_store.py` | `FileSystemProjectStore.save_novel()` | 保存小说原文到文件系统 |

## 4. LLM 客户端流程

### 4.1 调用流程

```
Pipeline Step 调用 LLM
        │
        ▼
   llm_client.chat(prompt, **kwargs)
        │
        ▼
   【检查：是否 JSON 模式？】
        │
        ├── 是：追加 "请严格按 JSON 格式输出"
        │
        └── 否：正常调用
        │
        ▼
   openai.ChatCompletion.create()
        │ 参数：model / temperature / max_tokens / messages
        │
        ▼
   【检查：响应格式】
        │
        ├── JSON 模式：
        │   ├── 尝试 json.loads(raw)
        │   ├── 成功：返回 dict
        │   └── 失败：自动修复 → 重试（最多 3 次）
        │
        └── 文本模式：
            └── 返回 raw text
```

### 4.2 错误处理流程

```
LLM 调用失败
        │
        ▼
   【判断错误类型】
        │
        ├── JSONDecodeError / ValidationError（输出格式错误）
        │   └── 自动修复 → 降级重试 → 标记 [PARSE_ERROR]
        │
        ├── 401 Unauthorized（Key 无效）
        │   └── 直接报错，不重试
        │
        ├── 429 Too Many Requests（限速）
        │   └── 指数退避重试（等待时间 = 2^attempt 秒）
        │
        ├── 500+（服务端错误）
        │   └── 重试 3 次，指数退避
        │
        ├── ConnectionError / Timeout（网络错误）
        │   └── 重试 3 次
        │
        └── 其他异常
            └── 记录日志，向上抛出
```

### 4.3 各方法作用

| 文件 | 方法 | 作用 |
|------|------|------|
| `llm_client.py` | `LLMClientProtocol.chat()` | LLM 调用协议：发送 prompt，返回文本 |
| `llm_client.py` | `LLMClientProtocol.chat_json()` | LLM 调用 + JSON 解析 |
| `llm_client.py` | `LLMClientProtocol.chat_stream()` | LLM 流式调用（V2） |
| `llm_client.py` | `OpenAIClient.chat()` | OpenAI API 兼容实现 |
| `llm_client.py` | `call_llm_with_retry()` | 带重试的 LLM 调用封装 |

## 5. 项目管理流程

### 5.1 项目创建流程

```
用户点击"新建项目"
        │
        ▼
   前端 → POST /api/v1/projects
        │ Body: { title, novel_text }
        │
        ▼
   ProjectStore.create_project()
        │
        ▼
   FileSystemProjectStore:
        │ 1. project_id = f"proj_{uuid4().hex}"
        │ 2. project_dir = ~/.novel2script/projects/<id>/
        │ 3. 写入 novel.txt（小说原文）
        │ 4. 写入 script.yaml（空）
        │ 5. 写入 meta.json（项目元信息）
        │ 6. 写入 config_snapshot.json（配置快照）
        │
        ▼
   返回 Project 对象 → 前端跳转到编辑器页面
```

### 5.2 项目打开流程

```
用户点击项目卡片
        │
        ▼
   前端 → GET /api/v1/projects/{id}
        │
        ▼
   ProjectStore.get_project()
        │
        ▼
   FileSystemProjectStore:
        │ 1. 读取 meta.json → ProjectMeta
        │ 2. 读取 novel.txt → 小说原文
        │ 3. 读取 script.yaml → YAML 剧本
        │
        ▼
   返回 ProjectDetail → 前端加载编辑器（恢复上次编辑状态）
```

### 5.3 自动保存流程

```
用户在编辑器修改内容
        │
        ▼
   CodeMirror 触发 update 事件
        │
        ▼
   debounce 定时器（2000ms）
        │
        ▼
   前端 → PUT /api/v1/projects/{id}/novel（或 /script）
        │ Body: { content }
        │
        ▼
   ProjectStore.save_novel()
        │ 1. 写入 novel.txt
        │ 2. 更新 meta.json（updated_at / novel_word_count）
        │
        ▼
   触发 SSE 事件：project_saved
        │
        ▼
   前端状态栏显示"已保存"
```

### 5.4 各方法作用

| 文件 | 方法 | 作用 |
|------|------|------|
| `core/project_store.py` | `ProjectStore.create_project()` | 创建新项目（协议） |
| `core/project_store.py` | `ProjectStore.get_project()` | 获取项目详情 |
| `core/project_store.py` | `ProjectStore.list_projects()` | 项目列表（支持搜索排序） |
| `core/project_store.py` | `ProjectStore.delete_project()` | 删除项目（软删除） |
| `core/project_store.py` | `ProjectStore.save_novel()` | 保存小说原文 |
| `core/project_store.py` | `ProjectStore.save_script()` | 保存 YAML 剧本 |
| `core/project_store.py` | `ProjectStore.update_beat()` | 更新单个 Beat |
| `core/project_store.py` | `FileSystemProjectStore.create_project()` | 文件系统实现：创建目录和文件 |
| `core/project_store.py` | `FileSystemProjectStore.get_project()` | 文件系统实现：读取项目数据 |

## 6. Skill 系统流程

### 6.1 Skill 发现流程

```
应用启动（lifespan）
        │
        ▼
   SkillManager.discover()
        │
        ▼
   【扫描 Skill 来源】
        │
        ├── BuiltinSkillSource:
        │   └── 扫描 src/skills/ 目录
        │       ├── fountain_export/
        │       ├── character_report/
        │       ├── dialogue_polish/
        │       ├── style_adapter/
        │       └── chapter_summary/
        │
        └── UserSkillSource:
            └── 扫描 ~/.novel2script/skills/ 目录
                └── 用户自定义 Skill
```

### 6.2 Skill 执行流程

```
用户点击"运行 Skill"
        │
        ▼
   前端 → POST /api/v1/skills/{name}/run
        │ Body: { data, config }
        │
        ▼
   SkillManager.execute(name, data, config)
        │
        ▼
   【检查 skill.json 的 requires_llm 字段】
        │
        ├── requires_llm = true（默认）：
        │   └── config 中包含 llm_client
        │
        └── requires_llm = false：
            └── 从 config 中移除 llm_client（节省资源）
        │
        ▼
   importlib.util.spec_from_file_location()
        │ 动态加载 main.py
        │
        ▼
   module.run(data, config)
        │
        ▼
   返回结果 → 前端展示
```

### 6.3 Skill 沙箱隔离流程（V2）

```
SkillManager.execute()
        │
        ▼
   【判断：是否为用户 Skill？】
        │
        ├── 否（内置 Skill）：
        │   └── 直接执行（信任代码）
        │
        └── 是（用户 Skill）：
            └── SkillSandbox.run_in_sandbox()
                │
                ▼
                创建子进程（asyncio.create_subprocess_exec）
                │ 参数：sys.executable + skill_main.py
                │ 限制：内存 100MB / CPU 时间 30 秒
                │
                ▼
                通过 stdin 传递输入数据（JSON）
                │
                ▼
                通过 stdout 读取输出结果（JSON）
                │
                ├── 超时：抛出 SkillTimeoutError
                ├── 非零退出码：抛出 SkillExecutionError
                └── 正常：解析 JSON 返回
```

### 6.4 各方法作用

| 文件 | 方法 | 作用 |
|------|------|------|

## 9. SSE 实时推送流程

### 9.1 SSE 连接建立流程

```
前端启动转换
        │
        ▼
   POST /api/v1/convert/start
        │ 返回 { task_id }
        │
        ▼
   前端创建 EventSource
        │ new EventSource(`/api/v1/convert/${task_id}/events`)
        │
        ▼
   【监听 SSE 事件】
        │
        ├── onmessage: `step_start`
        │   └── 更新进度条：显示"正在执行：{step_name}"
        │
        ├── onmessage: `step_progress`
        │   └── 更新进度条：显示百分比和详情
        │
        ├── onmessage: `step_complete`
        │   └── 进度条前进一格（共 6 步）
        │
        ├── onmessage: `task_complete`
        │   └── 跳转至编辑器页面
        │
        ├── onmessage: `task_failed`
        │   └── 显示错误信息和重试按钮
        │
        ├── onmessage: `skill_start`
        │   └── 显示"正在运行 Skill：{skill_name}"
        │
        └── onmessage: `skill_complete`
            └── 显示 Skill 执行结果
```

### 9.2 SSE 事件推送流程（后端）

```
Pipeline 执行（后台任务）
        │
        ▼
   ProgressCallback 被调用
        │
        ▼
   sse.py → SSEManager.send_event()
        │
        ▼
   【判断事件类型】
        │
        ├── step_start：
        │   └── 推送：{ event: "step_start", step, total_steps, current }
        │
        ├── step_progress：
        │   └── 推送：{ event: "step_progress", step, detail, percent }
        │
        ├── step_complete：
        │   └── 推送：{ event: "step_complete", step, result_summary }
        │
        ├── task_complete：
        │   └── 推送：{ event: "task_complete", result }
        │
        └── task_failed：
            └── 推送：{ event: "task_failed", error }
        │
        ▼
   Frontend EventSource 接收 → 更新 UI
```

### 9.3 各方法作用

| 文件 | 方法 | 作用 |
|------|------|------|
| `api/sse.py` | `SSEManager.add_client()` | 注册 SSE 客户端（按 task_id） |
| `api/sse.py` | `SSEManager.send_event()` | 向指定客户端推送事件 |
| `api/sse.py` | `SSEManager.remove_client()` | 移除客户端（断开连接） |
| `api/sse.py` | `sse_stream()` | SSE 事件流端点（GET /api/v1/convert/{task_id}/events） |

            └── src/prompts/ → novel2script/prompts/
        │
        ▼
   【生成可执行文件】
        │
        ├── EXE → novel2script.exe（Windows）或 novel2script（Linux/Mac）
        │   └── console=False（不显示控制台窗口）
        │
        └── COLLECT → dist/novel2script/ 目录
