## 质询 1：关于"3 章以上"的限制

### 问题

1. **为什么是 3 章？** 这个数字是拍脑袋决定的，还是基于测试？
2. **如果用户输入 2 章怎么办？** 是直接报错，还是允许转换但给出警告？
3. **"章"的定义是什么？** 是按"第 X 章"标题划分，还是按空行划分？如果用户小说没有"第 X 章"标题怎么办？

### 回答

1. 三章是需求要求的，理解为测试出来的。
2. 当前"章"的定义是靠正则匹配章节标题（第X章/节/幕/回、Chapter X、PART X），如果文本没有任何章标题，就整篇当作一个"全文"章处理。
   
   **问题**：题目要求3章以上输入，但无章标题的小说会被默默当1章处理不会报错；而且长文本单章会让LLM压力大。
   
   **建议**：补充智能分章策略——无章标题且文本≥6000字时，按空行密集处或场景跳转关键词自动分割，或者在编辑器中支持用户手动插入章节标记。
3. 见上面对第二个问题的回答。

### 改进措施

已在 PRD 中添加**"8. 智能分章策略"**章节，详细说明：
- 章标题正则匹配规则
- 无章标题时的处理策略（整篇当作一章）
- 智能分章策略（无章标题且文本≥6000字时自动分割）
- 章节长度限制（超长章节自动分段）

## 质询 2：关于"10 万字小说 5 分钟内生成"

### 问题

1. **这个时间是怎样测算的？** 是基于某个特定模型（如 GPT-4）的响应时间，还是平均值？
2. **如果用户使用慢速模型（如本地 Ollama）怎么办？** 5 分钟可能无法完成。
3. **进度推送的频率是多少？** 是每处理 1000 字推送一次，还是每完成一个 Pipeline 步骤推送一次？
4. **如果超时怎么办？** 是否有超时机制？超时后如何处理？

### 回答

1. 随便编的。
2. 每完成一个 Pipeline 步骤推送一次。
3. 还没有超时机制，超时设定为一个超长时间，要是这个都超时了，就说网络问题，并且继续等待加载，除非用户手动取消，否则不取消。

### 改进措施

1. **移除不准确的性能承诺**：已从 PRD 中移除"10 万字小说 5 分钟内生成"的描述。
2. **明确进度推送频率**：已在 PRD 中明确"SSE 实时进度推送：每完成一个 Pipeline 步骤推送一次"。
3. **添加超时机制**：已在 PRD 的"可靠性要求"中添加"超时机制：设置超长超时（1 小时），网络问题时继续等待，用户可手动取消"。

## 质询 3：关于"用户自选 AI"

### 问题

1. **6 个预设是哪些？** 是 GPT-4、Claude、Gemini 等吗？
2. **如果用户选择的模型不支持 JSON 输出怎么办？** 程序中是否有降级策略？
3. **如果用户 API Key 无效怎么办？** 是否有校验机制？
4. **如果用户使用本地模型（如 Ollama）怎么办？** 程序中是否有特殊配置？

### 回答

1. 六个月是编的，全部都要让用户自己接。
2. 没有，在提示词里面记得指定好返回格式，这样就一定会是json格式了。
3. 没有，这个不用，到时候将报错信息返回前端就行。
4. 不支持。

### 改进措施

1. **移除预设模型**：已将 PRD 中的"6 个预设"改为"用户自己配置模型（无预设）"。
2. **明确 JSON 输出策略**：已在 PRD 中明确"在提示词中指定返回格式，确保 JSON 输出"。
3. **错误处理**：已将 PRD 中明确"将报错信息返回前端"。

## 质询 4：关于"长文本智能分段"

### 问题

1. **为什么是 6000 字？** 这个数字是怎样确定的？如果模型上下文长度是 128K，6000 字是否太小？
2. **"200 字上下文窗口"的具体实现是什么？** 是取前一段的最后 200 字，还是取后一段的前 200 字？
3. **如果分段后，角色别名跨段怎么办？** 比如前一段称呼"小明"，后一段称呼"明哥"，程序能否合并？
4. **如果分段后，场景跨段怎么办？** 比如前一段是"场景 1"，后一段还是"场景 1"，程序能否合并？

### 回答

1. 可以根据上下文自动计算。
2. 没有具体实现，请仔细判断。
3. 哎，这个就要看代码的实现方案了，我不是很清楚，请在开发文档中进行方案介绍。

### 改进措施

1. **分段阈值自动计算**：已将 PRD 中"6000 字阈值"改为"根据模型上下文长度自动计算阈值"。
2. **上下文窗口具体实现**：已在 PRD 中添加"技术实现方案"，说明上下文窗口的实现方式（在 Prompt 中添加"前文摘要"字段）。
3. **跨段合并策略**：已在 PRD 中明确"分段合并时，跨段的角色别名和场景自动合并"。
