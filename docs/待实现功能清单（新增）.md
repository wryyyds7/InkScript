### P0（V1 发布前建议完成）

#### 🆕 1. 版本历史：逐句修改历史

**竞品参照**：WriterDuet 版本历史支持逐句修改记录

**现状**：现有 `待实现功能清单.md` 中有"版本历史"（功能 8/17），但只规划了"快照级"版本（每次保存生成一个快照），**没有逐句修改历史**。

**建议实现**：
```
Step 1: 在 EditMeta 中增加 operation log（操作日志）
  - 每次编辑操作（新增/修改/删除 Beat、修改小说原文）记录一条 log
  - 格式：{timestamp, user, action, beat_id, field, old_value, new_value}

Step 2: 实现"时间轴"视图
  - 编辑器右侧可折叠面板：按时间展示所有修改记录
  - 点击某条记录 → 高亮对应 Beat/文本

Step 3: 实现"逐句 Diff"功能
  - 选择两个版本快照 → 高亮所有差异（新增/删除/修改）
  - 可逐条确认是否保留

Step 4: 实现"回滚到某次操作"
  - 不只是回滚到某个快照，而是可以回滚到某次具体操作
```

**与现有规划的冲突**：无冲突，是现有"版本历史"功能的增强。

**验收标准**：
- 每次编辑操作都有记录
- 可查看完整修改历史时间轴
- 可选择任意两个版本做 Diff
- 可回滚到任意历史版本或任意操作

Step 2: 点击曲线上的某个点 → 自动定位到对应 Beat

Step 3: 情绪曲线支持"场景级"和"Beat 级"两种粒度切换
```

**与现有规划的冲突**：无冲突，是 V2 规划中"情绪走向曲线"的具体实现方案。

**验收标准**：
- 情绪曲线在编辑器内实时渲染
- 点击曲线点 → 自动定位到对应 Beat
- 支持场景级/Beat 级切换
- 情绪数据来自 YAML 中的 emotion 字段

#### 🆕 7. 剧本结构分析（幕次均衡、节奏分析）

**竞品：Arc Studio Pro 结构可视化**

**现状**：现有规划中没有剧本结构分析功能。

**建议实现**（作为 analyzer Skill）：
```
Skill 名称：structure-analytics
类型：analyzer

功能：
1. 幕次均衡分析
   - 检查各幕的场次/台词量是否均衡
   - 给出建议（如"第 2 幕场次过少，建议拆分或合并"）

2. 节奏分析
   - 计算各场景的情绪强度方差
   - 标记"情绪平淡区"（连续 3 个场景情绪强度 < 2）
   - 标记"情绪过山车区"（连续 3 个场景情绪强度变化 > 3）

3. 角色戏份分析
   - 计算每个角色的台词量占比
   - 标记"戏份过少角色"（占比 < 5%）
   - 标记"戏份过多角色"（占比 > 40%）

输出：结构化报告（JSON）+ 可视化图表（雷达图/柱状图/折线图）
```

**与现有规划的冲突**：无冲突，是完全新增的 Skill。

**验收标准**：
- Skill 正确分析剧本结构
- 输出结构化报告
- 可视化图表正确渲染

**与现有规划的冲突**：需要扩展 YAML Schema（在 Beat 模型中加 `alternatives` 字段），但这是向后兼容的扩展（加 `Optional` 字段）。

**验收标准**：
- YAML Schema 支持存储多版对话
- 编辑器 UI 支持管理备选版本

#### 🆕 10. AI 语音朗读（角色音色区分）

Step 2: 为每个角色分配不同音色
  - 自动分配：根据角色性别、年龄，自动选择合适的音色
  - 手动分配：用户可手动为每个角色选择音色

Step 3: 播放控制
  - 播放/暂停/停止
  - 快进/快退（按场景或 Beat）
  - 语速调节
```

**与现有规划的冲突**：无冲突，是完全新增的功能。

**验收标准**：
- 正确朗读剧本内容
- 不同角色使用不同音色
- 播放控制正常

#### 🆕 14. 协作功能（实时多人编辑 + 评论）

**竞品：WriterDuet 实时协作**

**现状**：InkScript 是**纯本地单用户工具**，完全没有协作功能。

**建议实现**（V3 功能，技术复杂度高）：
```
技术方案：
- 使用 WebSocket（如 Socket.IO）实现实时通信
- 使用 CRDT（如 Y.py）实现无冲突数据同步

功能：
1. 实时多人编辑
   - 显示其他协作者的光标位置（不同颜色区分）
   - 显示其他协作者的选中区域
   - 字符级冲突合并（基于 CRDT）

2. 评论功能
   - 在 Beat 上添加评论
   - 评论支持 @提及、回复、解决状态

3. 权限管理
   - 所有者/编辑者/评论者/只读 四种权限
```

**与现有规划的冲突**：需要引入 WebSocket 和 CRDT 依赖，架构改动较大。建议 V3 实现。

**验收标准**：
- 多人同时编辑无冲突
- 评论功能正常
- 权限管理正常

#### 🆕 15. 移动端适配（响应式编辑器）

**竞品：WriterDuet / Final Draft Mobile**

**现状**：InkScript 前端使用 Tailwind CSS，**理论上支持响应式**，但**没有针对移动端优化编辑器交互**。

**建议实现**（V3 功能）：
```
Step 1: 移动端布局优化
  - 默认上下分栏（小说原文在上方，YAML 剧本在下方）
  - 支持手势切换分栏比例

Step 2: 移动端编辑器交互优化
  - 双击 Beat → 弹出编辑弹窗（全屏）
  - 支持语音输入（移动端浏览器原生支持）

Step 3: 移动端离线支持
  - 使用 Service Worker 缓存前端资源
  - 离线时编辑内容存储在 LocalStorage，联网后自动同步
```

**与现有规划的冲突**：无冲突，是纯前端优化工作。

**验收标准**：
- 移动端布局正确
- 移动端编辑器交互流畅
- 移动端离线编辑正常

## 5. 总结

本文档在现有 `待实现功能清单.md` 基础上，结合 **2026 年竞品最新动态**，提出了 **15 项新增功能建议**：

**核心发现**：
1. **可视化是核心差异化方向**：竞品普遍具备情绪曲线、角色图谱、节拍板等可视化功能，InkScript 当前规划偏重"文本式"编辑，需要加强可视化能力。
2. **版本历史需要细化**：现有规划只有"快照级"版本，需要增强为"逐句修改历史"。
3. **制作素材派生是高价值扩展**：从剧本延伸到制片流程，可大幅提升工具的专业度。
4. **协作功能是长期方向**：纯本地工具适合个人用户，但团队协作是专业场景的刚需。

**下一步行动**：

3. 将 P2 新增功能加入 V3 开发计划
